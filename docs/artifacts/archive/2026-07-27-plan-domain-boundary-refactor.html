What can go wrong

The internal critique is GO because the highest-impact failure modes are turned into sequencing rules and tests, not reminders.

Server Folder shuffle masquerades as architecture

Migrate every caller and delete the old path in the same ticket. The import guard makes bypasses observable.

Data A transaction splits during extraction

One workflow owns multi-domain transactions; domain commands accept `DbOrTx`; fault injection proves rollback.

AH Uncertain external writes become generic errors

Keep explicit result states, history ordering, known-success bought state, and a hard ban on automatic retry.

Invariant English display names reach AH

A Dutch-specific purchase DTO plus divergent Dutch/English fixtures blocks the wrong field at the boundary.

AI Confirmation or preconditions move below the seam

The commit-risk gate stays above domain execution; HTTP/AI effect contracts prove the shared command.

Svelte Rune state leaks between instances

Use per-component factories and reactive object properties—not module singletons or exported reassigned `$state`.

UX Focus, undo, or resume breaks after markup moves

Characterize first; extract pure logic, then controllers, then markup; verify populated and error states at both viewports.

Scope Refactor absorbs redesign and features

Visible changes stay out. Record them separately after parity, so rollback and root-cause evidence remain clean.
