Mobile timer plan · 28 July 2026

The alarm must outlive the page.

Today the cooking page owns the deadline, the sound, and the “backup” notification. The plan moves the deadline to durable SQLite state and uses Web Push for the system alert, while keeping a short audible foreground alarm.

Recommendation SQLite job + Web Push

The current fallback is in the same failure domain

Source tracing shows that the service worker does not own a scheduled deadline. It only receives a message after page JavaScript notices expiry. Mobile suspension can stop the entire chain before any alert exists.

1 · Tap

The page starts a local timer and a 12-hour silent media track.

2 · Wait

A page Worker or interval keeps checking the wall-clock deadline.

3 · Mobile OS

The page, Worker, or media session can be suspended or killed.

4 · Fire

Only a surviving page tick calls the local alarm method.

5 · Notify

The page then messages the service worker at expiry.

Result

No page tick means no sound, vibration, or notification.

What the mobile web can honestly do

iOS 16.4+

Home Screen only

Installed web apps can receive standards-based Push and show Lock Screen notifications. Ordinary Safari tabs cannot.

PUSH API

Page may be inactive

A server push can wake the service-worker path after the cooking page has closed.

SOUND

Device default

Web notifications cannot choose a custom alarm sound or override silent and Focus settings.

TIMING

Not an alarm clock

Provider acceptance is not device delivery. Network and power policy can delay or drop the alert.

Architecture choice

Long silent media

Smallest patch, but still page-owned, cannot wake a killed PWA, and cannot restore playback without another gesture.

Reject

SQLite deadline + Web Push

Preserves the PWA and one-process deployment. It creates an independent OS-notification path with explicit readiness and test-alert states.

Choose

Capacitor native shell

Better offline scheduling, but adds iOS/Android projects, signing, stores, native permission/channel rules, and an API-origin/auth decision.

Defer

Managed sender

Adds a third-party account and data boundary while inheriting the same OS delivery and silent-mode limits.

Reject

The durable path

One timer alerts one originating device. Missing server configuration degrades to a clearly labelled foreground-only timer instead of blocking cooking.

1 · Enable

An explicit tap requests permission, creates a Push subscription, and offers a test alert.

2 · Schedule

The timer writes an idempotent UUID job tied to that user and device subscription.

3 · Persist

SQLite survives navigation, page eviction, and Node process restarts.

4 · Claim

The always-on Node scheduler atomically claims a due job and rejects stale work.

5 · Push

An encrypted, high-urgency payload uses short TTL and a stable dedupe topic.

6 · Alert

The service worker or declarative fallback shows a system notification and returns to cooking on tap.

The close gate is physical

Desktop automation cannot emulate a phone OS suspending or killing a PWA. The issue stays open until Android Chrome and an iOS 16.4+ Home Screen app each complete ten healthy-network timers with zero missing notifications.
