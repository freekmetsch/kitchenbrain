Stock Radar / fidelity recovery / design shotgun

Same plan. Three honest ways to make it look intentional.

Every direction keeps the approved behavior: outcome-first meals, explainable attention, first-class search, quiet recipe state, immediate quantity controls, and the complete stock ledger. The question is how literally the interface should return to the approved prototype.

Must restore

Olive/honey identity, serif hierarchy, Use next / Still plenty, compact ledger, and responsive intent.

Must preserve

Search, filters, edits, quantity writes, recipe relationships, ghost rows, English/Dutch, and dark theme.

Must avoid

Another generic white dashboard, a narrow filter sidebar, or ingredients appended beneath default Meals.

Direction A / recommended / highest fidelity

Prototype Literal

Treat the approved refinement as the visual contract: a substantial olive radar panel beside a warm compact ledger, with the same hierarchy compressed into mobile.

Main strength

It directly fixes the reported failure: the screen immediately reads as the approved Stock Radar.

Trade-off: More page-specific composition and a stronger desktop asymmetry.

Optimizes

Choosing a meal, seeing why it needs attention, then correcting quantity without leaving the ledger.

Direction B / strongest breakpoint continuity

Responsive Radar Band

Keep the olive identity as a full-width outcome band, then use a dense two-column ledger beneath it on desktop and the same stack on mobile.

Main strength

The same visual model survives every breakpoint and the desktop ledger gets maximum width.

Trade-off: It gives up the approved left-radar silhouette.

Optimizes

Fast stock maintenance across tablet and desktop, with attention kept visible as a band.

Direction C / calmest editorial reading

Editorial Pantry

Use large serif group headings, paper cards, and olive as a restrained accent. The hierarchy comes from typography and rhythm more than a dark panel.

Main strength

It is the calmest scan and gives Use next / Still plenty the clearest reading rhythm.

Trade-off: It is least faithful to the already-approved desktop identity.

Optimizes

Leisurely meal choice and content legibility over dashboard-like scanning.

Turn the visual choice into an implementation handoff

A is preselected because fidelity is the problem being repaired. Override it only if another composition is genuinely better, not because it is easier to implement.
