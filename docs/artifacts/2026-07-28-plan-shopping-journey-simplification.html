Recommendation

Choose Run Rail

Why it fits this app

Shopping already has one trustworthy aggregated list. Run Rail removes routing state around it instead of inventing source panels or an edit mode. Weekly ownership changes presentation only; source IDs and recipe revisions still own every persistent choice.

  • All controls requested by the brief remain visible.
  • Mixed weekly/recipe rows stay single and still match both filters.
  • Substitutes remain approved Dutch terms; AH product preferences remain separate.
  • Uncertain sends never offer Retry.

What disappears

  • Visible “Y left / X in basket” header copy
  • Permanent rail edge mask
  • Store Route and its lexical classifier
  • List options as a mobile router
  • Nested rules → editor sheets
  • “Back to this week”

Decision workspace

Defaults are ready, but taste still matters

Your selections and notes stay in this browser only. Untouched, the workspace hands off the recommended plan.

Which interaction direction should `/run` implement?

Run Rail best serves the repeated phone task. The alternatives emphasize provenance or batch maintenance.

When should the default advance after delivery?

The app stores a grocery day, not a delivery time. The safest date-only boundary keeps the current run for the full delivery day.

How should rule and substitute changes commit?

These choices persist to recipe-owned behavior. Explicit Save gives failure recovery a stable draft.

Where should recent AH activity live on phone?

The latest handoff affects the current run. Older attempts are history, not primary list content.
